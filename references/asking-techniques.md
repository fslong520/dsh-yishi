# 提问技术参考

> 来源：卡兹克《都Agent时代了，我还是想分享给你这12个我最常用的Prompt》
> 本文提炼其中`帮助AI更准确理解用户意图`之方法，供忆时在需求暧昧时使用。

## 核心原则

1. **一次只问一个问题** — 根据回答决定下一问，勿提前给整套问卷
2. **区分事实与判断** — 分清可验证之事实、对事实之解释、价值判断、欲实现之目标
3. **检查关键词** — 用户所用词汇是否含糊？默认了哪些前提？证据来自何处？
4. **只问可能改变结论的问题** — 信息足够即止，不必凑满次数
5. **每次追问前更新判断** — 用一句话说明上一回答让你更新了什么

## 苏格拉底式提问（意图澄清）

当用户需求模糊、目标不明时，用此流程替用户理清真正想问之事。

### 适用场景

- 用户一句话说目标，但无上下文
- 用户描述现象，未提真正卡点
- 用户要求"做一个"某物，但未定义功能边界
- 用户说"帮我看看/弄一下"，未说明具体问题

### 流程

**引导语**：先不要给建议，通过追问帮用户找到真正值得回答的问题。

**追问规则**：
1. 每次只问一个问题，根据回答决定下一问
2. 优先区分：可验证事实 vs 对事实的解释 vs 价值判断 vs 目标
3. 检查关键词是否含糊、默认前提、证据来源、有无相反解释
4. 每次提问前，用一句话说明上一条回答让你更新了什么判断
5. 只问可能改变结论的问题。信息足够时立刻停止

**结束输出**：
1. 用户最开始问的问题
2. 用户真正想解决的问题
3. 已确认的事实
4. 仍未验证的假设
5. 最可能改变结论的关键变量
6. 一个准确、具体、可继续行动的新问题

等用户确认这个新问题后，再给出判断、理由和下一步行动。

## 双层解释法（概念澄清）

当用户用模糊术语描述需求时，让AI以小白和专业双重角度确认理解一致。

### 适用场景

- 用户用行业术语，但不确定双方理解一致
- 用户说"像XX那样"，但未说明具体哪方面
- 需要确认AI理解的用户需求是否偏离

### 流程

1. **小白版** — 用生活化语言和具体例子复述用户需求
2. **专业版** — 用准确术语确认核心机制与边界
3. **输出**：列出口语表达与专业术语的对应关系 + 最容易理解错的地方 + 3个检查是否理解正确的问题

## 反向拆解（需求挖掘）

当用户给出一个成品/范例时，通过拆解其背后逻辑来理解真正需求。

### 适用场景

- 用户说"像XXX一样做"
- 用户给了一个链接或截图作为参考
- 需要理解用户为什么觉得某个东西好

### 流程

1. 先说明它解决了什么问题
2. 再反向拆解它为什么有效
3. 重点分析：目标用户是谁→结构/流程→关键选择→完成标准→哪些可迁移、哪些只适合此案例
4. 输出：3-5条可复用规律 + 可执行操作清单 + 第一步尝试

---

## 事实核查（信息验证）

当用户给出需验证的信息时，区分事实与判断，避免基于错误前提作答。

### 适用场景

- 用户提供了前提/数据/观点，但不确定准确性
- 信息涉及具体数字或外部事件
- 需要联网确认

### 流程

1. 拆成：可验证的事实 → 从事实推出的结论 → 价值判断
2. 对事实标级：已证实 → 基本成立但需收窄 → 存在争议 → 证据不足 → 明显错误
3. 检查：事实能否推出结论 → 是否藏未经验证的假设 → 是否混淆相关性与因果 → 是否遗漏其他解释
4. 输出：可信部分 / 需修正部分 / 推理链中最关键漏洞 / 可相信程度

## 第一性原理（需求本质）

当用户需求层叠复杂、打满补丁时，回归最底层问题。

### 适用场景

- 用户提需求时带着多个预设方案
- 需求经过了多层"别人说应该这样"的过滤
- 需要判断"用户真正要什么"而非"用户说想要什么"

### 流程

1. 区分：已确认的基本事实 → 习惯性接受但未验证的假设 → 真正想实现的目标 → 现实约束
2. 放下行业惯例与现成方案，只从基本事实、目标和约束出发
3. 输出：原方案中只在修补表面的部分 / 重新推导出的新路径 / 路径成立的前提 / 验证第一步

## 专家会诊（多角度确认）

当用户需求可能涉及多个专业领域时，让AI以多种互补视角验证理解。

### 适用场景

- 需求跨领域（如"做个AI教学平台"涉及技术+教育+设计）
- 用户一句话需求，但背后涉及多个层面
- 需要不同角度验证是否理解全面

### 流程

1. 选择3种真正互补的专业视角，说明每种视角之必要
2. 每种视角：怎样重新定义问题 / 最推荐的路径 / 其他视角易忽略的风险
3. 让三种视角互相质疑：共同认可的事实 / 真正的分歧 / 分歧背后的假设
4. 输出：综合方案 / 适用条件 / 最大风险 / 退出条件 / 第一步行动

## 跨领域借解（跳出思维定势）

当同一思路反复打转时，从其他领域找相似问题的解法。

### 适用场景

- 用户和AI围绕同一方案反复讨论无进展
- 需求描述中隐含了行业惯例限制
- 需要跳出固定思维框架

### 流程

1. 剥掉行业术语，抽象成人类在其他领域也可能遇到的问题
2. 找出底层结构、核心矛盾、普通解法失效的原因
3. 从至少3个彼此距离较远的领域找底层结构相似问题
4. 每个案例说明：领域问题 → 解决机制 → 相似点 → 可迁移部分 → 失效条件
5. 选最值得借用的3种机制，翻译成当前环境之方案

## 双向钢人论证（决策验证）

当有两种可能的需求解释时，分别论证再定。

### 适用场景

- 用户需求可被两种不同方式理解
- 有两个可能的方向，不知选哪个
- 需要验证"用户更可能想要A还是B"

### 流程

1. 重述真正需要做出的选择
2. 分别给出两个方向的最强理由、适用条件、最大收益、最大风险
3. 找出双方真正的分歧、最可能改变结论的关键变量
4. 只问一个最可能改变结论的问题
5. 获回答后，给出明确判断、理由、适用条件

---

## 最小实验（验证假设）

当理论讨论无法推进时，用最小可逆实验代替空想。

### 适用场景

- 需求理解有多种可能，但无法靠推理确定
- 需要先做一个小东西验证方向
- 用户说"试试看"但不确定试什么

### 流程

1. 找出此决定背后最需验证的3个假设
2. 选最可能改变最终结论的一个
3. 设计低成本、可逆、限时完成的最小实验
4. 写清：具体做什么 / 投入多少 / 观察什么指标 / 什么结果支持继续 / 什么结果提醒停止
5. 明天就能开始的第一个动作
